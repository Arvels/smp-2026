# Крок 2. П'ять передбачень SQL

## A. `SELECT 7 / 2, 7 / 2.0`

**Передбачення:** `3 | 3.5`, тому що ділення двох цілих чисел у SQLite дає цілу частину, а число `2.0` робить результат дробовим.

**Показала:** `3 | 3.5`. **Я вгадав**, бо SQLite використала цілочисельне ділення для `7 / 2`, а для `7 / 2.0` — дійсне.

## B. `SELECT COUNT(*), COUNT(Composer) FROM Track`

**Передбачення:** перше число — кількість усіх рядків таблиці `Track`, друге — кількість рядків, у яких `Composer` не дорівнює `NULL`; друге число може бути меншим за перше.

**Показала:** `3503 | 2526`. **Я вгадав**, бо `COUNT(*)` врахував усі 3503 записи, а `COUNT(Composer)` — лише 2526 записів із непорожнім (`NOT NULL`) значенням `Composer`.

## C. `SELECT 'Abba' LIKE 'a%', 'Abba' = 'abba'`

**Передбачення:** `1 | 0`, тому що `LIKE` для латинських літер зазвичай не враховує регістр, а `=` порівнює рядки з урахуванням регістру.

**Показала:** `1 | 0`. **Я вгадав**, бо `'Abba' LIKE 'a%'` істинне, а `'Abba' = 'abba'` — хибне.

## D. `SELECT Composer FROM Track ORDER BY Composer LIMIT 1`

**Передбачення:** `NULL`, якщо у стовпці `Composer` є пропущені значення, оскільки SQLite під час сортування за зростанням розміщує `NULL` першими.

**Показала:** `NULL`. **Я вгадав**, бо в таблиці `Track` є записи з `Composer = NULL`, а SQLite за зростанням сортує їх перед текстовими значеннями.

## E. `SELECT NULL OR 1, NULL AND 1`

**Передбачення:** `1 | NULL`, оскільки `OR` з істинним значенням дає істину, а `AND` із невідомим і істинним дає невідоме.

**Показала:** `1 | NULL`. **Я вгадав**, бо в першому виразі достатньо істинного операнда, а в другому результат залишається невідомим.
