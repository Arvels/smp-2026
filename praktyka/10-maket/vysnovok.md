# Робота 10. Висновок: три менеджери макета Tkinter

```text
  ✅ форма повна, поля в колонку з підписами, кнопки внизу праворуч
  ⭐ вікно розтягнули на 200 px — поля розтягнулись разом із ним

== form_pack.py
  ✅ форма повна, поля в колонку з підписами, кнопки внизу праворуч
  ⭐ вікно розтягнули на 200 px — поля розтягнулись разом із ним

== form_place.py
  ✅ форма повна, поля в колонку з підписами, кнопки внизу праворуч
  ·  вікно розтягнули на 200 px — поля лишились тієї самої ширини (для place це очікувано — запишіть у vysnovok.md)

Разом: 3 з 3 форм ✅   (мінімум для зарахування — grid і ще одна)
```

## Висновок (6 речень)

Для цієї форми реєстрації найкраще підійшов `grid`, тому що чотири пари «підпис — поле» природно розташовуються у двох стовпцях і залишаються рівно вирівняними.
Найважче в `grid` було правильно налаштувати `columnconfigure(weight=1)` і `sticky="ew"`, щоб поля змінювали ширину разом із вікном.
У `pack` найскладніше було створити окремі `Frame` для кожного рядка та задати підписам однакову ширину, інакше поля не стояли б в одній колонці.
У `place` найбільше часу зайняв ручний підбір координат `x` і `y` для кожного елемента, особливо для кнопок унизу праворуч.
Перший експеримент із розтягуванням вікна показав, що поля у `grid` і `pack` збільшуються, а у `place` залишаються на своїх фіксованих місцях та не змінюють ширину.
Другий експеримент із заміною «Скасувати» на «Abbrechen und zurück» показав, що `grid` і `pack` пристосовуються до довшого тексту без перекриття кнопок, тоді як у `place` кнопки можуть перекриватися через фіксовані координати.
